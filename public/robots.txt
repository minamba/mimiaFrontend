# CE FICHIER NE SERT PAS À RETIRER UNE PAGE DE GOOGLE — 26/10/2026.
# Il interdit de LIRE une page, pas de l'indexer. Une adresse fermée ici mais
# liée ailleurs (le bouton « Espace enfant » mène à /code) est indexée quand
# même, sans contenu : Google ne peut pas lire le « noindex » d'une page qu'on
# lui interdit d'ouvrir. C'est l'alerte « Indexée malgré le blocage par le
# fichier robots.txt » reçue de la Search Console.
#
# Les pages privées (/eleves, /profil, /admin, /code) sont donc LISIBLES : le
# serveur leur répond avec l'en-tête « X-Robots-Tag: noindex », et la page pose
# la balise robots du même nom. Le robot lit, et ne garde rien. Il n'y voit
# rien non plus : sans connexion, ces pages n'affichent qu'un formulaire.
#
# Restent fermées les seules pages qui AGISSENT à l'ouverture ou portent un
# jeton dans leur adresse — un robot qui exécute le JavaScript pourrait
# consommer un lien de scan, un retour de connexion ou un désabonnement.
# Aucune n'est liée depuis une page publique.
#
# CE FICHIER NE PROTÈGE RIEN. La protection des données, c'est
# l'authentification côté API.
#
# LA LISTE DOIT SUIVRE FERMEES_AUX_ROBOTS dans src/lib/seo/pages.js
# (vérifié par sitemap.test.js).
